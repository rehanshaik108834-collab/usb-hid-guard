Method

How a keyboard earns a block

System C collects evidence in three layers and adds it up. No single weak sign is enough, so a fast barcode scanner is flagged but never cut off.

Descriptor layer

What the device claims

Checked once at plug-in: the whitelist, known attack-board IDs, a VID:PID already used by another connected device, a storage-and-keyboard combination, and a missing serial number.

Timing layer

How fast it types

The median gap between key presses, once at least {{ p.min_keys }} keys have arrived, compared with {{ p.median_threshold_ms }} ms. Recomputed as more keys arrive. Shift and other modifier keys are ignored.

Content layer

What it types

The key presses are turned back into text. Shortcuts that open a command prompt and words such as {{ p.keywords[:4]|join(', ')|safe }} add points.

Example shown: a keyboard copying a connected keyboard's ID (+30) that types faster than {{ p.median_threshold_ms }} ms a key (+50) scores 80.

Block or hold

Proof: typing faster than any person can is proof of injection. The device is blocked at once: its keys are cut off and real USB hardware is switched off through its authorized file.

Suspicion without proof (for example a new keyboard typing powershell): the device is held. Its keys stop reaching the computer and a {{ p.challenge.digits if p.challenge else 4 }}-digit code appears here and in the detector's terminal. A person types the code on the new keyboard and it is unlocked; an injection device cannot see the screen, so it stays blocked.
